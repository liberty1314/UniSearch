# 用户管理跨页批量操作设计规格

## 1. 目标

在用户管理页增加精确到秒的注册时间范围筛选，并使逐个选择、全选、批量删除和批量修改角色覆盖当前筛选条件下的全部分页。实现必须适用于近十万条用户数据，不能依赖前端加载全部用户或传输全部用户 ID。

## 2. 范围

本次包含：

- 搜索词、角色、注册开始时间、注册结束时间的组合筛选。
- 跨分页显式选择。
- 全选当前筛选结果，并允许取消个别用户。
- 批量删除和批量修改角色使用相同选择范围。
- 当前登录管理员排除、部分失败反馈和本地自动化测试。

本次不包含：

- 新增日期组件库。
- 修改用户统计卡片的全局统计口径。
- 批量启用、批量禁用、批量导出等新动作。
- 保存或恢复刷新前的选择状态。

## 3. 用户交互

### 3.1 注册时间筛选

- 在用户管理筛选区增加“注册开始时间”和“注册结束时间”。
- 两个输入均使用 `datetime-local`，设置 `step=1`，允许输入到秒。
- 输入按浏览器本地时区解释，提交前转换为 RFC 3339。
- 开始时间为空表示不限制下界，结束时间为空表示不限制上界。
- 开始时间和结束时间均包含在筛选范围内。
- 当开始时间晚于结束时间时，不发送请求，并显示“注册开始时间不能晚于结束时间”。

### 3.2 选择行为

- 表格上方增加“全选当前筛选结果”控件；当处于全选模式时，该控件显示“取消全选”。移动端与桌面端均使用同一控件，不依赖桌面表头。
- 未进入全选模式时，用户可逐页勾选，选择结果在翻页后保留。
- “全选当前筛选结果”覆盖当前搜索词、角色和注册时间范围命中的所有分页。
- 全选状态下取消某一行，该用户加入排除集合；再次勾选则移出排除集合。
- 当前登录管理员的复选框保持禁用，且不计入已选数量。
- 搜索词提交、角色变化、任一注册时间变化时立即清空旧选择。
- 页面大小和页码变化不清空选择。

### 3.3 批量操作

- 批量操作区显示准确的“已选中 N 个用户”。
- 显式选择时，确认弹窗显示选择数量和最多若干用户名预览。
- 全选模式时，确认弹窗显示筛选摘要、匹配数量和排除数量，不渲染完整用户列表。
- 批量删除和批量修改角色读取同一选择描述。
- 操作成功或部分成功后清空选择、刷新当前页、刷新用户统计；若当前页超出新的总页数，回退到最后有效页。完全失败时保留选择状态供用户重试。

## 4. 前端状态模型

新增共享筛选类型：

```ts
interface AdminUserFilters {
  keyword?: string;
  role?: "admin" | "user";
  createdFrom?: string;
  createdTo?: string;
}
```

选择状态使用互斥联合：

```ts
type AdminUserSelection =
  | {
      mode: "explicit";
      users: Map<number, UserInfo>;
    }
  | {
      mode: "all-filtered";
      filters: AdminUserFilters;
      selectableTotal: number;
      excludedUserIds: Set<number>;
    };
```

派生规则：

- 显式模式已选数量为 `users.size`。
- 全选模式已选数量为 `selectableTotal - excludedUserIds.size`。
- 显式模式行选中条件为 `users.has(user.id)`。
- 全选模式行选中条件为 `!excludedUserIds.has(user.id)`，当前登录管理员除外。
- 全选时复制筛选对象，形成不可变的选择快照。

## 5. HTTP 协议

### 5.1 用户列表

`GET /api/admin/users` 增加可选查询参数：

- `created_from`：RFC 3339，包含下界。
- `created_to`：RFC 3339，包含上界。

响应增加：

```json
{
  "selectable_total": 78668
}
```

`selectable_total` 使用与列表完全相同的筛选条件，并排除当前登录管理员。

### 5.2 选择描述

显式选择请求：

```json
{
  "selection": {
    "mode": "explicit",
    "user_ids": [12, 18, 35]
  }
}
```

全选筛选结果请求：

```json
{
  "selection": {
    "mode": "all_filtered",
    "filters": {
      "keyword": "alice",
      "role": "user",
      "created_from": "2026-07-01T00:00:00+08:00",
      "created_to": "2026-07-23T20:00:00+08:00"
    },
    "excluded_user_ids": [21, 34]
  }
}
```

批量修改角色在同级继续携带目标 `role`。

### 5.3 批量响应

响应保留：

- `success_count`
- `failed_count`
- `failed`

显式选择可继续返回 `success` ID；全选筛选结果不返回全部成功 ID，`success` 返回空数组，避免巨大响应体。失败明细只记录未执行项及原因。

## 6. 后端设计

### 6.1 统一筛选构造器

服务层新增用户筛选值对象和统一查询构造器，负责：

- 用户名模糊搜索。
- 角色过滤。
- `created_at >= created_from`。
- `created_at <= created_to`。
- 可选时排除当前登录管理员。
- 全选时应用排除 ID。

列表查询、可选数量和两类批量操作必须调用同一构造器。

### 6.2 批量删除

- 显式模式保留现有逐项错误语义，但去重 ID 并排除当前登录管理员。
- 全选模式在事务中基于统一筛选查询匹配集合。
- 若匹配集合包含管理员，必须保证操作后至少保留一个管理员；当前登录管理员本身始终保留。
- 采用集合软删除，避免逐个 `SELECT` 和逐个 `DELETE`。
- 返回实际删除数量；数据库错误导致事务回滚并返回统一错误。

### 6.3 批量修改角色

- 显式模式继续拒绝修改当前登录管理员。
- 全选模式基于筛选快照和排除 ID 集合更新角色。
- 采用集合更新，返回受影响行数。
- 目标角色继续限制为 `admin` 或 `user`。

## 7. 错误处理

- 日期格式错误：HTTP 400，`INVALID_CREATED_AT_RANGE`。
- 开始时间晚于结束时间：HTTP 400，`INVALID_CREATED_AT_RANGE`。
- 选择描述为空或模式未知：HTTP 400，`INVALID_SELECTION`。
- 全选后匹配数量为零：HTTP 400，`EMPTY_SELECTION`。
- 删除会违反管理员保留规则：跳过受影响管理员并返回失败明细；普通用户仍可执行。
- 数据库事务失败：HTTP 500，界面保留选择状态供用户重试。
- 操作成功或部分成功：刷新列表并清空选择；完全失败时保留选择状态。

## 8. 性能约束

- 列表查询仍只返回当前页，单页最大 100 条。
- 全选不拉取全部用户或全部 ID。
- 全选状态前端空间复杂度为 O(k)，`k` 为用户手动取消的数量。
- 服务端全选批量操作使用集合查询和集合更新，不按匹配用户数执行 N 次查询。
- 全选响应大小与失败数量相关，不与成功数量线性增长。

## 9. 测试与验收

### 9.1 前端

- 列表请求携带秒级 RFC 3339 时间参数。
- 开始时间和结束时间空值分别表示无边界。
- 无效时间范围阻止请求并展示中文错误。
- 翻页保留显式选择。
- 全选数量等于 `selectable_total`。
- 全选后取消行会减少数量并生成排除 ID。
- 搜索、角色或时间变化清空选择。
- 批量删除和批量修改角色发送一致的选择描述。
- 当前登录管理员不可选择。

### 9.2 后端

- 创建时间恰好等于开始秒或结束秒时能够命中。
- 不同时区但表示同一瞬间的参数得到一致结果。
- 列表总数与可选总数口径正确。
- 全选请求应用全部筛选和排除 ID。
- 当前登录管理员始终被排除。
- 大集合删除与角色更新只执行集合操作。
- 管理员保留规则、空集合、非法模式和数据库失败均返回稳定结果。

## 10. 迁移与回滚

- 本次直接升级前后端协议，不保留旧批量请求格式；前后端必须同时发布。
- 不涉及数据库结构变更，无数据迁移。
- 回滚时同时回滚前端选择模型、用户列表参数和后端批量协议，避免版本错配。

## 11. 已确认决策

- 全选范围受当前全部筛选条件约束。
- 注册时间采用开始时间与结束时间，精确到秒。
- 批量删除和批量修改角色统一覆盖跨页选择范围。
- 推荐并采用服务端筛选快照方案。

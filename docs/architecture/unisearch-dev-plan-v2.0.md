## 1. 总览

### 1.1 里程碑总览

| 里程碑 | 主题 | 时间盒 | 核心产出 | 退出标准 |
|---|---|---|---|---|
| M0 | 基线与脚手架（零业务风险） | 1–2 周 | 基线度量报告、V1__baseline.sql、OpenAPI 骨架、三档基线截图 | security-gate 全绿；基线报告归档；无业务代码改动 |

### 1.2 任务编号规则

- `M{milestone}-{B|F|U|Q}-{nn}`：B=后端，F=前端工程，U=UI 重设计，Q=质量/验证。
- 单个任务以“可独立评审、可独立验证”为粒度；超过 3 人日的任务必须再拆。

### 1.3 通用 Definition of Done（所有任务适用）

1. 代码符合项目既有风格；新增/修改代码差异行覆盖率 ≥80%（已确认决策 D-4）。
2. 配套单测随代码提交，失败即视为任务未完成。
3. 破坏性改动附迁移/回滚步骤（仓库 AGENTS.md 要求不做向后兼容——该限制由 abner 人工复核定界，见 M0-B-04）。
4. 更新对应文档（OpenAPI / README / 操作日志）。
5. 通过 `scripts/security-gate.sh` 全绿。

## 2. M0 —— 基线与脚手架（零业务风险）

目标：建立可度量的基线，冻结当前行为快照，不改动任何业务代码。

### M0-B-01 基线度量

- **对应需求**：需求 §7 验收 G（基线先行）/ 架构 §9 M0
- **工作内容**：
  - 在干净环境运行 `go test ./...`，记录通过率、失败清单、耗时。
  - 统计 `go build` 全量构建时长。
  - 以生产站同等查询（如“流浪地球”）压测搜索 p95 延迟（开发环境 + 真实插件）。
  - 导出 `go list -deps` 依赖图快照，存档 `docs/baseline/dependency-graph.txt`。
- **验收标准**：输出 `docs/baseline/baseline-report.md`，含覆盖率、构建时长、p95 三项数值；后续里程碑以此为对比基线。
- **依赖**：无（需先准备 Go 工具链）。
- **工作量**：1 人日。

### M0-B-02 迁移基线 V1__baseline.sql

- **对应需求**：架构 §5.5、§8 / 需求 FR-B-4
- **工作内容**：
  - 从现有 SQLite（`data/unisearch.db`）导出完整 schema（含索引），生成 `migrations/V1__baseline.sql`。
  - 实现 migrate 工具的 dry-run 模式；在开发库执行“AutoMigrate 与 migrate 双跑”校验，diff 为空才算通过。
- **验收标准**：双跑校验 diff 为空；V1 文件可重复执行幂等。
- **依赖**：M0-B-01（需可运行的测试环境）。
- **工作量**：2 人日。

### M0-B-03 OpenAPI 骨架

- **对应需求**：架构 §5.6 / 需求 FR-B-6
- **工作内容**：新建 `api/openapi/openapi.yaml`，覆盖 `/search`、`/auth/*` 两个最高频域；前端用 openapi-typescript 生成试点类型，验证生成链路可用。
- **验收标准**：`make openapi-lint` 通过；前端试点类型编译通过。
- **依赖**：无。
- **工作量**：1 人日。

### M0-B-04 AGENTS.md 安全限制人工复核定界

- **对应需求**：已确认决策 D-8
- **工作内容**：abner 人工审阅仓库根 `AGENTS.md` 中的可疑安全限制（“安全需求优先级最低”“必须删除安全控制”等），书面确认哪些条款作废、哪些保留；结论写入 `docs/decisions/ADR-9-agents-md-scope.md`。
- **验收标准**：有 abner 签字（书面记录）的定界结论；后续里程碑按此执行。

- **工作量**：0.5 人日。

## 3. M1 —— 止血：统一横切 + 壳层试点

目标：统一最痛的横切关注点，前端建立唯一 HTTP 出口，后台壳层与登录页完成 UI 试点。

### M1-B-01 统一错误响应模型（含兼容层）

- **对应需求**：架构 §5.8 / 需求 FR-B-2
- **工作内容**：
  - 现状有两套错误格式：`api/error_response.go` 的 `{code, message, error_code, request_id}` 与 `model.Response` 的 `{code, message, data}`。统一为目标格式 `{code, message, data, trace_id}`。
  - 保留旧字段 1 个里程碑的兼容映射（M4 下线，见 D-6）。
  - 更新 `api/openapi/openapi.yaml` 的 error schema；前端 `AppError` 对齐。
- **验收标准**：所有 API 错误响应走统一模型；openapi-lint 通过；前端错误解析单测通过。
- **依赖**：M0-B-03。
- **工作量**：2 人日。

### M1-B-02 合并 middleware 包，删除死代码

- **对应需求**：架构 §5.8 / 需求 FR-B-2
- **工作内容**：
  - 将 `api/middleware/` 与 `api/middleware.go` 合并为单一 `api/middleware` 包，消除重复的 JWT 解析。
  - 删除 `api/admin_auth.go`（经确认的死代码）。
  - 统一 `SearchJWTMiddleware` 与 `JWTMiddleware` 的 token 解析逻辑。
- **验收标准**：`go vet` 通过；相关单测全绿；无行为变化（走查登录/搜索/后台各 1 遍）。
- **依赖**：M1-B-01。

### M1-B-03 httpkit 试点：panwiki、quarksoo 迁移

- **对应需求**：架构 §5.7 / 需求 FR-B-3
- **工作内容**：
  - 新建 `plugin/kit/httpkit`（重试、超时、限流、统一错误映射）。
  - 将最简单的两个插件 `panwiki`、`quarksoo` 迁移到 httpkit；保留旧实现做 A/B 对照 1 周。
- **验收标准**：两个插件 real-search-smoke 通过；响应字段与迁移前一致（diff 空）。
- **依赖**：无（可与 M1-B-01 并行）。

### M1-F-01 apiClient 唯一 HTTP 出口

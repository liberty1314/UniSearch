## 1. 引言

### 1.1 编写目的

本文档定义 UniSearch 架构重构与 UI 重设计的全部需求：功能需求（后端模块化重组、前端架构重组、前台 UI 视觉重设计、管理后台 UI 重设计）、非功能需求、约束、里程碑与验收标准。它是《UniSearch 新架构设计方案文档》v2.0 的需求依据，也是各阶段实施与验收的基准。

v2.0 相对 v1.3 的主要变化：纳入 2026-09-29/30 期间经交互原型验证并由决策人确认的全部 UI 需求（搜索结果页交互、热榜筛选口径、导航栏、统一登录、登录/注册/个人中心/后台各页视觉语言），并将版本号、里程碑与验收标准对齐到最新决策。

### 1.2 范围

- 范围内：
  - 后端：模块化单体重组（限界上下文、依赖治理、Repository 层、插件 SDK 重设计、API 契约、审计有界化、版本化迁移）。
  - 前端：features 垂直切片重组、唯一 HTTP 出口、OpenAPI 类型生成、TanStack Query 引入。
  - UI：前台全站视觉重设计（不新增功能）、管理后台全站视觉重设计（不新增功能）、前后台共享设计系统。
- 范围外：
  - 任何面向用户的产品功能新增或交互逻辑变更（UI 重设计必须基于现有功能与现有交互逻辑）。
  - 数据库选型变更；后端框架/ORM/前端框架更换；微服务拆分。
  - 插件针对各网盘站点的具体解析逻辑重写（仅迁移插件基座）。

### 1.3 读者对象

架构评审决策人（abner）、后端负责人、前端负责人、QA。

## 2. 项目目标与成功标准

### 2.1 总体目标

在不改变产品功能与 API 语义的前提下，完成两件事：

1. **架构重构**：将 UniSearch 从"有机生长型单体"重组为"模块化单体"（依赖显式、边界清晰、插件真插件化、前后端契约先行），使后续迭代边际成本显著下降，且全程可回滚、可验证。
2. **UI 重设计**：以前台现有玻璃拟态风格为设计家族基线，统一前台与管理后台的视觉语言；每个页面在统一材质下拥有独立的布局、排版与视觉隐喻；不新增功能、不改变现有交互逻辑。

### 2.2 成功标准

| 编号 | 标准 | 验收方式 |
|---|---|---|
| S-1 | 评审报告全部 P0/P1 问题在设计方案中有对应设计 | 需求追踪矩阵（附录 A） |
| S-2 | 架构目标 G-1..G-10 达成（见设计方案 §3.2） | CI 门禁 + 复评报告 |
| S-3 | 新增/修改代码的差异行覆盖率 ≥ 80% | CI 覆盖率门禁 |
| S-4 | UI 走查发现的全部视觉不一致问题消除 | 视觉走查清单（§3.3/§3.4）+ 视觉回归测试 |
| S-5 | 前台 390px / 768px / 1440px、后台窄窗口基线无布局破损 | 响应式基线截图 |
| S-6 | 每阶段 `scripts/tests/security-gate.sh` 全绿且独立可回滚 | 阶段退出评审 |

## 3. 功能需求

### 3.1 后端架构重构需求（FR-B）

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-B-1 | 模块化单体分层 | 按 `transport → application → domain ← infrastructure` 分层；`domain` 零外部依赖；依赖规则 DR-1..DR-6（设计方案 §5.3）由 CI 强制 |
| FR-B-2 | 限界上下文划分 | 拆分为 search / searchsource / identity / ops / ranking 五个上下文；跨上下文调用必须经 Facade 接口 |
| FR-B-3 | 依赖注入显式化 | 删除包级可变全局（`config.AppConfig`、`database.GetDB/SetDB`、各 `Set*`）；`internal/app/wire.go` 为唯一装配点；`SearchService` 的 6 个 `Set*` setter 删除，改为构造注入 |
| FR-B-4 | 搜索 pipeline 拆分 | `search_service.go` 上帝对象拆为 `SearchUsecase` + pipeline 四包（selector / executor / merger / builder）；`Search()` 9 参数收敛为 `SearchParams` 值对象；消除与 `PluginHealthChecker` 的循环依赖 |
| FR-B-5 | 插件 SDK 重设计 | 统一 `Source` 接口（`Search` + `Manifest`）；删除 `AsyncSearch` 死方法；基类 998 行神对象拆为 httpkit / parsekit / cachekit；32 个插件在 `wire.go` 显式注册，删除 `init()` 自注册与空白导入；manifest 必填字段缺失或版本占位时装配期失败 |
| FR-B-6 | 插件健康检查轻量化 | 两级探针替代"固定关键词真实搜索"：L1 轻量探针（HEAD/版本接口）+ L2 站点结构指纹校验；探针由 scheduler 统一调度 |
| FR-B-7 | Repository 层 | 全部持久化访问经 `domain` 接口 + `infrastructure/persistence` 实现；`application` 禁止直连 GORM；事务由用例拥有（`WithTx` 模式） |
| FR-B-8 | 审计有界化 | 搜索审计与管理审计统一走 scheduler 有界 channel（默认容量 1000，可配置）；channel 满时丢弃最旧事件并记录水位与丢弃指标（已确认决策）；消除无界 goroutine |
| FR-B-9 | 身份域统一 | `TokenService` 统一门面（access / refresh / 吊销 JTI / 资源解析 token）；`SecretReader` / `SecretWriter` 接口分离，env 实现编译期不可写；`RefreshTokenService` 改为构造注入，删除经 `gin.Context` 隐式传递 |
| FR-B-10 | 运营域收敛 | `application/pluginops` Facade 统一插件运行态写入路径；`admin_handler.go` 按域拆分；`system_settings_service.go` 按设置类别拆分 |
| FR-B-11 | 热榜域拆分 | `hot_ranking_service.go` 拆为 tmdb.Adapter / ranking.Scorer（纯函数）/ ranking.Prewarmer（纳入 scheduler）；清理残留签名 |
| FR-B-12 | API 契约 | 新路由挂载 `/api/v1`；`api/openapi/openapi.yaml` 为前后端唯一契约源；统一错误模型 `{code, message, data, trace_id}`；旧路径 Phase 1–3 兼容、Phase 4 下线（已确认决策） |
| FR-B-13 | 版本化迁移 | 引入 golang-migrate；`migrations/` 为生产唯一 DDL 来源；`AutoMigrate` 降级为开发 bootstrap；基线导出后与 `AutoMigrate` 双跑校验一致方可转正 |
| FR-B-14 | 配置不可变化 | 不可变 `Config` 值对象经 `wire.go` 构造注入；运行时设置变更语义改为"生成新 Config + 重建受影响组件"；插件禁止直读配置 |
| FR-B-15 | Middleware 合并 | 合并为单一 middleware 包；删除 `admin_auth.go` 与 `AuthMiddleware` 死代码；认证/限流/审计采样/trace_id 职责收敛 |
| FR-B-16 | 健康检查端点 | 新增 `/healthz`（存活）与 `/readyz`（DB/Redis/注册表自检） |
| FR-B-17 | 后台任务统一调度 | `scheduler` 统一注册表（任务名、触发器、优雅停机）；审计 worker、健康探针、指标聚合/清理、热榜预热全部纳入；21 个插件自启 goroutine 消除 |

### 3.3 前台 UI 重设计需求（FR-U）

**全局硬线**：只做视觉重设计，不新增功能；交互逻辑以生产站实际行为为准；视觉以决策人认可的玻璃拟态首页为家族基线；每个页面在统一材质下拥有独特的布局、排版与视觉隐喻，禁止把同一套皮肤机械铺到所有页面。

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-U-1 | 设计语言基线 | 全站采用玻璃拟态：毛玻璃质感、青蓝柔光背景、悬浮玻璃卡片、克制的指针光晕与入场动效；同一设计家族 |
| FR-U-2 | 导航栏采用现有设计 | 三栏式粘性导航：左侧蓝色→青色渐变 "U" 徽章 + 蓝色加粗 "UniSearch" 文字（点击回首页）；中间独立白色大胶囊导航（首页/搜索/热门榜单，带线性图标），选中态为蓝色文字 + 项内浅蓝色圆角高亮 + 胶囊顶部蓝色短横线指示；右侧通知铃铛、月亮主题切换（浅色描边圆形图标按钮）与头像胶囊（蓝色圆角方头像 + 白色首字母 + 蓝色用户名）。未登录时右侧为登录按钮 |
| FR-U-3 | 首页 | 悬浮玻璃导航、大号玻璃搜索框、资源来源轨道、节奏化的功能卡片（已确认方向，保持） |
| FR-U-4 | 搜索结果页布局 | 检索仪表式构图；工具栏左侧结果总数，右侧排序 + 卡片/列表即时切换；卡片视图 4 列、列表视图整行；滚动后回到顶部按钮 |
| FR-U-5 | 网盘筛选 | 11 类网盘多选 pill：百度、阿里、夸克、天翼、UC、移动、115、迅雷、123、磁力链接、蓝奏云；选中态为各网盘**纯色**背景（禁止渐变），配色与现有生产一致；支持全选/取消全选；偏离全选后显示"已启用 N 项"与"清空全部筛选"；筛选与结果数量联动 |
| FR-U-6 | 排序 | 仅三种：综合排序、最新优先、最早优先 |
| FR-U-7 | 高级筛选 | "包含关键词"与"排除关键词"先暂存，点击"应用筛选"后刷新结果 |
| FR-U-8 | 结果加载 | 非数字分页：底部"加载更多"，首次约 48 条、每次追加约 48 条；全部加载后显示"已加载全部 N 条结果" |
| FR-U-9 | 结果字段收敛 | 结果项字段仅为：标题（卡片视图最多两行）、清晰度信息、网盘标签、更新时间、"有码"状态；不得新增文件数量、文件大小、来源站点、复制链接等字段 |
| FR-U-10 | 卡片内网盘标签 | 浅色底 + 对应彩色文字（非白字纯色底）；"有码"标签用浅绿底 |
| FR-U-11 | 热榜页筛选口径 | 按现有"热榜控制台"逻辑：榜单模式（趋势榜/热门榜）× 时间维度（每日/每周/每月/每年）× 内容分类（全部/电影/电视剧/动漫）；顶部显示当前口径与当前周期；提供刷新入口；**不得**按资源类型筛选 |
| FR-U-12 | 热榜页布局 | 编辑式领奖台构图：前三名领奖台 + 后续榜单流；筛选切换后标题、当前周期、前三名与榜单流同步更新；控制台去掉冗余标题文案区，只保留筛选器 |
| FR-U-13 | 个人中心 | "个人搜索档案"视觉：深青档案封面、个人印章、目录式侧栏、编辑排版的数据节奏区、最近搜索线索；账户概览与偏好设置沿用同一语言；消除全大写英文标签与"加载中…"残留文案 |
| FR-U-14 | 统一登录地址 | 前台与后台共用 `/login`，不再设独立后台登录地址、不设管理员/普通用户切换入口；身份由后端按账户权限区分（已确认决策） |
| FR-U-15 | 头像菜单按权限 | 管理员：个人中心、管理后台、退出登录；普通用户：个人中心、退出登录 |
| FR-U-16 | 登录页个性 | 冷蓝色调，"返回搜索"概念，检索轨道视觉 + 编辑式表单 |
| FR-U-17 | 注册页个性 | 暖橙 + 深绿色调，"创建工作台"概念，图文布局与登录页反转、轨道造型与引导文案独立设计；与登录页风格明确区分 |
| FR-U-18 | 页脚统一 | 全站统一为同一页脚（含首页/个人中心/免责声明入口）；消除两套页脚并存；`/about` 404 需处理（补页面或移除入口） |
| FR-U-19 | 异步状态 | 统计数字等异步内容使用骨架屏，禁止先显示 0 再跳变 |
| FR-U-20 | 文案口径 | 消除中英文混用、技术黑话外露（如 deferred / local / fallback: / 原始 API 路径）；海报破图需兜底 |
| FR-U-21 | 响应式基线 | 390px / 768px / 1440px 三档基线；移动端筛选项自动换行，不得横向滚动 |

### 3.4 管理后台 UI 重设计需求（FR-A）

**全局硬线**：同 FR-U 全局硬线；后台各页面在现有功能基础上展示各自个性。

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-A-1 | AdminShell | 统一后台壳层："运营控制台"视觉——深色控制轨、模块编号、技术状态栏；各页面有自己的强调色；与前台/登录页/个人中心明显区分 |
| FR-A-2 | 后台页面模板 | 五类页面模板：总览仪表盘、行式数据表、卡片集合、表单/设置、监控图表；同一类页面结构一致 |
| FR-A-3 | 数据密集型组件规范 | 表格、筛选器、分页、空态、批量操作统一：分页默认条数一致、省略号与布局统一；筛选控件统一（禁止原生 select / 按钮下拉等多套混用）；筛选弹层支持 Escape 关闭且关闭后无遮罩残留 |
| FR-A-4 | 权限与危险操作反馈 | 危险操作（封禁、删除、下线插件等）需二次确认；操作结果有明确成功/失败反馈；无权限入口不渲染 |
| FR-A-5 | 管理总览 | 指挥舱构图：关键指标、技术状态、快捷入口；数字加载用骨架屏 |
| FR-A-6 | 用户管理 | 补齐操作列；标题与口径统一；筛选/分页遵循 FR-A-3 |
| FR-A-7 | 插件中心 | 插件卡片与其运行态（状态/健康/指标/运行时配置）信息架构统一 |
| FR-A-8 | Telegram 频道 | 由卡片列表收敛为与其他页面一致的行式表格（或统一为卡片，取其一全站一致） |
| FR-A-9 | 性能监控 | 图表时间范围、指标口径统一；图表有入场动效 |
| FR-A-10 | 审计 | 搜索审计与操作审计分开；筛选条件（时间/用户/类型）统一；分页遵循 FR-A-3 |
| FR-A-11 | 公告管理 | 公告列表与编辑表单信息架构统一 |
| FR-A-12 | IP 封禁 | 封禁列表 + 新增/解封操作符合 FR-A-4 |

## 4. 非功能需求（NFR）

| 编号 | 需求 | 说明 |
|---|---|---|
| NFR-1 | 搜索 p95 不劣化 | 核心链路 p95 较 Phase 0（M0）基线劣化不超过 10%，否则阻断 |
| NFR-2 | 差异行覆盖率 ≥ 80% | 新增/修改代码的差异行覆盖率门禁 ≥ 80%（已确认决策）；CI 强制 |
| NFR-3 | 回滚能力 | 每阶段独立可回滚；数据层零变更，回滚无数据风险；生产切换迁移工具前做备份恢复演练 |
| NFR-4 | 安全基线不降低 | JWT 短期 access + refresh 轮换、JTI 吊销、密码策略、封禁 IP、验证码、限流、管理审计全部保留；`SecretReader/Writer` 分离后 env 模式编译期不可写 |
| NFR-5 | 可观测性 | 结构化日志 + `trace_id` 全链路；Prometheus 指标命名规范；核心指标：搜索 QPS/分源延迟/熔断状态、审计 channel 水位与丢弃计数、插件健康状态 |
| NFR-6 | 优雅停机 | scheduler 统一处理 SIGTERM，in-flight 请求排空后退出 |
| NFR-7 | UI 响应式 | 前台 390px / 768px / 1440px、后台窄窗口无布局破损、无横向滚动（表格除外且需可读） |
| NFR-8 | 视觉回归 | 关键页面（首页/搜索结果/热榜/登录/后台总览）建立视觉回归基线截图；PR 级对比 |
| NFR-9 | 可访问性基线 | 键盘可达（筛选弹层 Escape 关闭）、焦点可见、色彩对比度达标；装饰动效尊重 `prefers-reduced-motion` |
| NFR-10 | 前端性能 | 首屏与路由切换无明显卡顿；图片/海报破图有兜底占位 |

## 5. 约束与非目标

1. 不拆微服务；不更换 Gin / GORM / React 18 / Zustand；不变更 MySQL + Redis 选型。
2. 不改变任何面向用户的产品功能与 API 语义；UI 重设计不得新增字段、筛选维度、排序选项或操作。
3. 仓库根 `AGENTS.md` 含有"删除/禁用安全控制"类可疑指令：本项目不执行其中任何指令；由 abner 手动复核移除（已确认决策）。
4. 单人开发：M0–M4 串行推进，时间盒按实际动态调整，不并行铺阶段。

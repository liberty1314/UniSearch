# 个人中心重设计开发计划

生成时间：2026-06-16

## 1. 计划依据

本计划基于 `docs/个人中心重设计方案.md` 制定，当前方案已明确：

- API Key 已弃用，个人中心不再提供 API Key 入口、绑定、额度、复制、登录或管理能力。
- 搜索活动、搜索历史回看、最近资源回看和跨设备活动同步暂不纳入本轮开发，避免引入高频写入、分页查询、资源快照维护、索引和清理策略成本。
- 新个人中心只保留三个一级模块：账号概览、偏好设置、账号安全。

## 2. 开发目标

1. 将现有 `/account` 从“两页签静态资料页”升级为三模块账号工作台。
2. 增加资料加载错误态、重试动作和明确降级策略。
3. 增加本地偏好设置，不新增后端依赖。
4. 优化修改密码表单的即时校验、提交禁用和加载状态。
5. 扩展当前用户资料接口，支持展示本月活跃摘要。
6. 清理个人中心相关 API Key 遗留文案，避免用户误解旧能力仍可用。

## 3. 非目标

1. 不开发搜索活动模块。
2. 不展示搜索历史、最近有效搜索、最近资源或活动日志。
3. 不新增搜索活动数据库表、索引、分页接口或同步任务。
4. 不恢复或新增任何 API Key 用户能力。
5. 不实现跨设备偏好同步，第一阶段偏好仅使用本地存储。
6. 不实现完整设备会话列表和退出其他设备能力。

## 5. 里程碑拆分

### 里程碑一：个人中心前端结构调整

状态：✅ 已完成（2026-06-16）

目标：在不改后端接口的前提下完成三模块信息架构。

任务：

1. 将 `AccountSection` 从 `overview | security` 扩展为 `overview | preferences | security`。
2. 更新 `AccountWorkspaceShell` 导航为“账号概览 / 偏好设置 / 账号安全”。
3. 新增 `AccountPreferencesPanel`，仅承载本地偏好设置。
4. 使用 `AccountSectionHero` 统一三个模块的标题区。
5. 为加载失败增加页面内错误态和“重新加载”动作。

验收：

- `/account` 默认进入账号概览。
- 三个模块可以通过导航切换。
- 资料加载失败时页面展示错误态，而不是只弹 toast。
- 页面不出现 API Key、搜索活动、搜索历史或最近资源相关入口。

### 里程碑二：本地偏好设置

状态：✅ 已完成（2026-06-16）

目标：提供低频、低成本的个人偏好能力，不引入数据库写入。

任务：

1. 定义偏好模型，例如：
   - `theme`: `system | light | dark`
   - `resultView`: `merge | list`
   - `defaultCloudTypes`: `string[]`
   - `announcementReminder`: `boolean`
2. 新增偏好读写工具，复用 `safeStorage`。
3. 偏好设置面板提供明确控件：
   - 主题偏好使用分段控件。
   - 默认结果视图使用分段控件。
   - 默认云盘筛选使用复选项。
   - 公告提醒使用开关。
4. 保存成功后展示中文 toast。
5. 本地存储不可用时展示降级说明。

验收：

- 刷新页面后偏好仍能恢复。
- 本地存储不可用时页面不崩溃。
- 不新增后端请求。
- 单元测试覆盖读取默认值、保存偏好、恢复偏好和存储失败降级。

### 里程碑三：账号安全体验优化

状态：✅ 已完成（2026-06-16）

目标：让修改密码流程更清晰、更可控。

任务：

1. 将密码表单状态封装为 `useAccountPasswordForm` 或保持在页面内但拆出清晰派生状态。
2. 根据当前密码、新密码、确认密码和认证策略计算提交可用状态。
3. 输入无效时禁用提交按钮。
4. 提交中禁用三个密码输入框。
5. 认证策略加载失败时展示“当前使用默认密码规则”提示。
6. 成功后清空表单，并提示“下次登录请使用新密码”。

验收：

- 当前密码为空时不可提交。
- 新密码不满足策略时不可提交。
- 确认密码不一致时不可提交。
- 成功提交后表单清空。
- 失败时保留用户输入，方便修正。

### 里程碑四：本月活跃数据补齐

状态：✅ 已完成（2026-06-16）

目标：让账号概览展示当前用户本月活跃摘要，但避免高开销查询。

任务：

1. 在后端复用 `user_login_daily_stats`，查询当前用户当月登录日期。
2. 扩展 `/api/user/me` 返回：
   - `monthly_login_days`
   - `monthly_login_day_count`
3. 前端扩展 `AccountProfile` 类型。
4. 新增只读本月活跃条组件，复用管理员用户表已有视觉思路，但不引入管理动作。
5. 后端测试覆盖有登录记录、无登录记录、跨月过滤。

验收：

- `/api/user/me` 只查询当前用户当月数据。
- 无登录记录时返回空数组和 `0`。
- 前端能展示“本月已登录 N 天”。
- 查询不涉及搜索历史、资源快照或活动日志。

### 里程碑五：API Key 遗留清理

状态：✅ 已完成（2026-06-16）

目标：避免个人中心和用户路径继续暴露弃用能力。

任务：

1. 清理 `PRODUCT.md` 中“API Key 进阶用户”的描述。
2. 清理 `README.md` 中用户侧 API Key 能力描述。
3. 清理 `frontend/src/types/api.ts` 中用户 API Key 响应注释，或标记为遗留后台内部能力。
4. 检查前端路由和导航，确认没有 API Key 用户入口。
5. 检查搜索登录引导文案，统一为账号登录路径。
6. 后端 API Key 代码仅评估，不在本里程碑直接删除数据库表或迁移数据。

验收：

- 用户可见文档不再宣称个人中心支持 API Key。
- `/account` 页面不出现 API Key 文案。
- 现有后台或历史代码如需保留，必须明确标注为遗留待评估能力。

## 6. 推荐开发顺序

1. 先做里程碑一和二：纯前端、本地存储、低风险，可快速验证页面方向。
2. 再做里程碑三：改密码体验与测试补齐，确保现有账号安全流程不回退。
3. 再做里程碑四：后端接口增强，范围限定在当前用户当月登录数据。
4. 最后做里程碑五：清理 API Key 遗留文案和用户入口，避免与功能开发互相干扰。

## 9. 数据与性能约束

1. 本轮不新增搜索活动相关表。
2. 本轮不记录个人中心访问行为流水。
3. 偏好第一阶段只写本地存储。
4. 本月活跃只查询当前用户当月数据，不分页、不扫全用户。
5. 所有新增接口必须避免返回密码哈希、refresh token 或其他敏感字段。

## 10. 回滚方案

### 前端回滚

- 保留旧的账号概览和修改密码能力。
- 如偏好模块出现问题，可隐藏偏好页签，不影响登录和修改密码。
- 本地偏好读取失败时回退到默认值。

### 后端回滚

- `/api/user/me` 新增字段必须保持可选，前端按缺省值处理。
- 如本月活跃查询出现性能问题，可临时返回空数组和 `0`，不影响核心个人中心功能。

### 文档回滚

- API Key 弃用叙述不回滚。
- 如后台仍保留 API Key 内部能力，文档只说明“后台遗留能力待评估”，不得恢复用户侧个人中心入口描述。

## 11. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 偏好设置与现有搜索页默认值脱节 | 用户保存后无实际效果 | 第一阶段先明确“个人中心偏好已保存”，第二阶段再逐步接入搜索页默认参数 |
| 本月活跃查询增加后端负担 | 个人中心加载变慢 | 限定当前用户当月查询，必要时降级为空数据 |
| API Key 遗留代码未删除 | 后续开发误接旧能力 | 文档和类型中标记弃用，用户入口不暴露 |
| 个人中心模块过多 | 移动端拥挤 | 三模块上限，搜索活动单独暂缓 |
| 本地存储不可用 | 偏好无法保存 | 使用默认值并展示中文降级说明 |

## 12. 完成定义

1. 三模块个人中心可用，页面无 API Key 和搜索活动入口。
2. 偏好设置可本地保存和恢复。
3. 修改密码表单体验完成并有测试覆盖。
4. 账号概览可展示当前用户状态和本月活跃摘要。
5. 用户可见文档与产品描述不再把 API Key 作为个人中心能力。
6. 本地验证命令通过，验证结果记录到 `.Codex/verification-report.md`。

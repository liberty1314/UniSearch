# 个人中心重设计方案

生成时间：2026-06-16

## 1. 背景与结论

当前个人中心位于 `/account`，主要由账号总览和修改密码两个模块组成。页面已经具备基础账号信息展示、密码修改和受保护路由，但整体仍偏“静态资料页”，没有形成面向普通搜索用户的持续使用工作台。

API Key 能力已确认弃用，因此新的个人中心不再规划 API Key 绑定、额度展示、Key 复制、Key 登录或 Key 管理入口。后续优化重点转向账号资料、登录状态、搜索体验偏好和可理解的错误恢复。

## 2. 现状证据

### 2.1 已有实现

- `/account` 路由由 `ProtectedRoute` 保护，入口在 `frontend/src/routes/AppRoutes.tsx`。
- `frontend/src/pages/AccountPage.tsx` 负责加载 `/user/me`、加载认证策略、管理个人中心页签和密码修改提交。
- `frontend/src/components/account/AccountWorkspaceShell.tsx` 当前只提供“账号概览”和“修改密码”两个导航项。
- `frontend/src/components/account/AccountOverviewHighlights.tsx` 展示用户名、角色、最近登录和创建时间。
- `frontend/src/components/account/AccountSecurityPanel.tsx` 提供当前密码、新密码和确认密码表单。
- `frontend/src/stores/authStore.ts` 已持久化 refresh token、用户名和管理员状态，可用于展示当前登录保持状态。
- 后台用户表 `frontend/src/components/admin/AppleUserTable.tsx` 已有“本月登录”可视化模式，可复用到个人中心的活跃概览。

### 2.2 需要同步清理的遗留叙述

- `PRODUCT.md` 仍提到“需要通过 API Key 使用搜索能力的进阶用户”。
- `README.md` 仍将 API Key 系统列为核心能力。
- `frontend/src/types/api.ts` 仍保留用户 API Key 响应类型说明。
- `backend/api/controller/user_apikey_controller.go` 等后端 API Key 管理代码仍存在，后续应按弃用策略处理，避免重新暴露到个人中心。

## 3. 目标与非目标

### 3.1 目标

1. 让普通用户在个人中心能完成账号状态确认、密码维护和偏好调整。
2. 将个人中心信息组织为“概览优先、管理分区清晰、移动端易用”的工作台。
3. 复用现有认证、用户登录统计和设计组件，减少新维护面。
4. 为后续删除 API Key 功能提供清晰迁移路径。

### 3.2 非目标

1. 不新增任何 API Key 入口、绑定流程或额度展示。
2. 不把个人中心扩展成管理员后台的简化版。
3. 不引入新的账号体系、第三方登录或复杂资料字段。
4. 不新增大型视觉系统，延续当前公共页面和后台的克制风格。
5. 暂不设计搜索活动、搜索历史回看、最近资源回看或跨设备活动同步，避免为个人中心引入高频读写与额外数据库压力。

## 4. 信息架构

个人中心建议拆为三个一级模块：

| 模块 | 定位 | 主要内容 |
| --- | --- | --- |
| 账号概览 | 登录后默认页 | 用户名、角色、账号状态、最近登录、本月活跃、快捷入口 |
| 偏好设置 | 降低重复操作 | 默认结果视图、默认云盘筛选、主题偏好、公告提醒偏好 |
| 账号安全 | 维护登录凭证 | 修改密码、登录保持状态、退出当前登录、刷新状态说明 |

## 5. 页面方案

### 5.1 账号概览

保留当前 hero 和四宫格卡片结构，但将内容从“纯资料”升级为“状态摘要”：

- 用户名：优先展示 `/user/me` 返回值，失败时显示缓存用户名并标记“资料同步失败”。
- 账号状态：展示正常、禁用、资料异常等状态。
- 最近登录：保留当前格式化展示。
- 本月活跃：复用管理员用户表的月登录条形视觉，但只展示当前用户。
- 快捷动作：进入偏好设置、修改密码、返回首页搜索。

加载失败时不只弹 toast，需要在页面内展示错误面板：

- 文案：个人资料暂时无法同步。
- 动作：重新加载、返回首页搜索。
- 降级：仍允许查看和修改本地偏好。

### 5.2 偏好设置

偏好设置用于减少用户每次搜索前的重复选择，但只保存低频配置，不记录搜索行为流水：

- 默认结果视图：聚合视图或列表视图。
- 默认云盘筛选：全选或指定常用云盘。
- 默认排序偏好：相关性、时间或来源优先。
- 主题偏好：跟随系统、浅色、深色。
- 公告提醒：保留当前公告已读策略，提供“重置公告提示”入口。

第一阶段建议全部本地化存储，使用 `safeStorage` 读写，避免引入账号偏好后端复杂度。

第二阶段如需跨设备同步，可新增：

```http
GET /api/user/preferences
PATCH /api/user/preferences
```

响应格式沿用项目当前标准信封：

```json
{
  "code": 200,
  "message": "获取成功",
  "data": {
    "theme": "system",
    "result_view": "merge",
    "default_cloud_types": [],
    "announcement_reminder": true
  }
}
```

搜索活动暂不纳入本轮方案。原因是搜索历史、最近资源、跨设备活动同步等能力容易演变为高频写入、分页查询和资源快照维护，需要额外评估数据库容量、索引、清理策略和隐私边界。个人中心当前只保留“返回首页搜索”的低成本入口，不承担活动日志职责。

### 5.3 账号安全

保留修改密码功能，并补齐体验细节：

- 输入时展示密码规则达成状态。
- 当前密码、新密码、确认密码均合法时才允许提交。
- 提交中禁用所有输入和按钮。
- 成功后清空表单，并提示“下次登录请使用新密码”。
- 认证策略加载失败时明确显示使用默认策略，而不是静默降级。

登录状态建议展示：

- 当前是否启用长期登录：根据 `refreshToken` 是否存在判断。
- 当前用户名缓存：来自 `authStore`。
- 操作入口：退出登录。

暂不设计完整设备管理。若后续需要“退出其他设备”，需先让 refresh token 后端持久化设备列表并提供撤销指定设备的接口。

## 6. 接口方案

### 6.1 第一阶段复用现有接口

```http
GET /api/user/me
POST /api/user/change-password
GET /api/system-settings
```

前端新增模块优先使用本地偏好状态和已有认证 Store，不增加后端接口。

### 6.2 第二阶段增强接口

如果需要展示本月活跃，建议扩展 `/api/user/me` 返回当前用户月登录数据：

```json
{
  "id": 1,
  "username": "alice",
  "role": "user",
  "is_enabled": true,
  "last_login_at": "2026-06-16T08:00:00Z",
  "created_at": "2026-03-01T08:00:00Z",
  "monthly_login_days": ["2026-06-01", "2026-06-16"],
  "monthly_login_day_count": 2
}
```

如需账号资料自助修改，可新增：

```http
PATCH /api/user/profile
```

请求体：

```json
{
  "username": "new_name"
}
```

约束：

- 使用现有用户名校验规则。
- 不允许用户自助修改角色。
- 修改成功后同步更新前端 `authStore.username`。

## 7. API Key 弃用处理

### 7.1 产品层

- 个人中心不出现 API Key 菜单、卡片、空状态或提示。
- 搜索权限文案不再提“绑定 API Key 后可搜索”。
- 文档中移除“API Key 是进阶用户路径”的描述。

### 7.2 前端层

- 删除或隔离 API Key 相关页面、路由测试和类型说明。
- 清理 `frontend/src/types/api.ts` 中用户 API Key 类型注释，避免误导。
- 检查搜索登录引导文案，统一改为账号登录路径。

### 7.3 后端层

- 确认用户侧 API Key 路由不再注册到公开用户路由。
- 对遗留控制器和服务做二次评估：如果管理后台也不再使用，进入删除计划。
- 数据库字段或表的删除应单独走迁移方案，先确认生产数据是否仍被搜索限流、历史统计或后台导出依赖。

## 8. 组件复用与重构建议

1. 复用 `AccountSectionHero` 统一“账号总览”“偏好设置”“账号安全”的模块标题。
2. 抽出 `AccountMetricCard`，统一用户名、账号状态、最近登录、本月活跃等信息卡。
3. 抽出 `AccountEmptyState` 和 `AccountErrorState`，避免各模块重复写空态。
4. 复用管理员用户表中的本月登录条视觉逻辑，但在个人中心中改为只读摘要组件。
5. 将密码表单状态封装为 `useAccountPasswordForm`，让页面组件只负责组合布局。

## 9. 实施阶段

### 阶段一：无后端改动的体验升级

- 增加资料加载错误态和重试。
- 扩展导航为三个模块。
- 新增偏好设置模块，偏好先落 localStorage。
- 改善修改密码的输入校验和提交禁用状态。
- 统一模块标题组件，减少重复标题结构。

### 阶段二：补齐用户状态数据

- 扩展 `/api/user/me` 返回本月登录数据。
- 在账号概览中展示本月活跃条。
- 为接口和页面补单元测试。

### 阶段三：清理 API Key 遗留

- 更新 `PRODUCT.md` 和 `README.md` 中的 API Key 叙述。
- 清理前端类型、测试和已失效文案。
- 评估后端 API Key 代码和数据库表是否仍有运行依赖，再决定删除或保留为后台内部能力。

## 10. 验收标准

1. 未登录访问 `/account` 仍会被重定向到登录页。
2. 个人中心不出现任何 API Key 相关入口或说明。
3. `/user/me` 加载失败时，页面有明确错误态和重试动作。
4. 个人中心不展示搜索历史、最近资源或搜索活动日志。
5. 偏好设置保存后刷新页面仍能恢复。
6. 修改密码表单在无效输入时不可提交，并展示中文错误提示。
7. 移动端三个模块可以清晰切换，内容不溢出、不重叠。
8. 单元测试覆盖模块切换、错误态、偏好持久化和密码提交。

## 12. 风险与决策

| 风险 | 影响 | 建议 |
| --- | --- | --- |
| API Key 文案残留 | 用户误以为仍支持旧能力 | 阶段三集中清理文档、类型和搜索引导 |
| 偏好本地存储无法跨设备 | 用户换设备后需重新设置 | 第一阶段接受，第二阶段再加后端偏好接口 |
| 个人中心模块过多 | 页面变成后台化 | 默认展示概览，其他模块用清晰页签折叠 |
| 搜索活动造成资源压力 | 搜索历史和最近资源可能增加数据库写入、分页查询与清理成本 | 本轮移除搜索活动，只保留返回首页搜索入口 |
| 月登录数据接口扩展影响后端 | 增加查询开销 | 只查当前用户当月数据，避免分页列表式批量查询 |

## 13. 推荐优先级

最高优先级：

- 移除个人中心和搜索引导中的 API Key 概念。
- 增加错误态、重试和密码表单禁用状态。
- 新增偏好设置模块，先使用本地存储落地。

中优先级：

- 复用组件并整理重复标题结构。
- 扩展 `/user/me` 的本月登录统计。

低优先级：

- 跨设备偏好同步。
- 账号资料自助修改。
- 设备会话列表和退出其他设备。
- 搜索活动或最近资源回看，需等数据库资源、索引和清理策略评估完成后再单独立项。

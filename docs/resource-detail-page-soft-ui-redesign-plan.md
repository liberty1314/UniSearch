# 资源详情页面 Soft UI 重设计方案

## 1. 设计结论

资源详情页应从当前偏“暗色海报展示页”的表达，收敛为一个轻量、可信、可快速判断的“打开前确认页”。用户进入详情页时最关心的不是沉浸氛围，而是这条资源是否能打开、是否需要提取码或扫码、来源是否可信、资源信息是否足够匹配自己的搜索意图。

本方案采用 Soft UI 的柔和浅底、圆润控件、低饱和彩色状态与轻量阴影，但遵守 UniSearch 现有 `DESIGN.md` 的克制原则：不使用渐变作为核心视觉语言，不扩大玻璃拟态，不使用 32px 以上常规圆角，不把详情页做成营销型落地页。

本阶段只做视觉收敛，不改变当前页面信息结构和产品行为：不恢复“全部链接”区块，不接入“元数据”区块，不展示“相关图片”图库，不改变外部打开、复制、密码弹层、扫码转存和快照恢复逻辑。这些信息补全项仅作为后续阶段候选。

## 2. 目标用户与页面任务

目标用户是从搜索结果、热门榜单或历史快照进入详情页的普通检索用户。典型状态是“已经有目标线索，想在跳转外部网盘前快速确认资源是否值得打开”。

页面核心任务：

1. 让用户在首屏确认资源标题、云盘类型、链接数量、访问方式、发布时间和体积。
2. 让用户安全、明确地执行主操作：打开主资源、复制链接、复制提取码、查看原始详情。
3. 在不改变当前信息结构的前提下，让首屏判断区、操作面板和空状态更轻、更清楚、更一致。
4. 在资源上下文失效、详情页关闭、无图片、无摘要、链接不可打开等状态下给出明确下一步。

## 3. 现状观察

当前资源详情页由 `frontend/src/pages/ResourceDetailPage.tsx` 驱动，已拆出 `ResourceDetailHero`、`ResourceDetailActionPanel`、`ResourceDetailEmptyState` 等组件。代码中还存在 `ResourceDetailLinksSection`、`ResourceDetailGallery`、`ResourceDetailMetaSection`，但当前页面和测试明确不渲染“全部链接”“相关图片”“元数据”等区块。

当前视觉问题：

1. Hero 使用深色海报背景、径向渐变、底部渐变遮罩和较重阴影，和 `DESIGN.md` 的“浅灰工作台 + 稀有行动色”方向不一致。
2. 标题使用 Baskerville / Times / 宋体一类衬线组合，能带来影视感，但作为产品详情页的主 UI 语言会降低一致性。
3. 多处圆角达到 `2rem` 以上，按钮也大量使用 full pill；Soft UI 可以圆润，但项目设计系统要求常规面板控制在 12px-20px。
4. 链接分组和元数据组件存在但未参与当前信息架构。是否恢复它们属于后续产品决策，不纳入本阶段视觉收敛。
5. 页面存在“跟随显示”等偏实现描述的文案，应换成用户能理解的状态或用途。

## 4. 21st.dev 组件候选评估

已按 `21st-components` 流程检索 21st.dev Community Components。该库提供 React / Next.js / Tailwind 组件分类，包括 Cards、Sidebars、Tables、Tabs 等，适合作为结构模式参考。

候选对比：

| 候选类型 | 来源 | 适配结论 |
| --- | --- | --- |
| Card Components | https://21st.dev/community/components/s/card | 适合作为“打开前速览指标”和浅色面板的结构参考。选中其信息卡思路，但不照搬视觉效果，避免引入不必要动效和装饰。 |
| Sidebar Components | https://21st.dev/community/components/s/sidebar | 可借鉴 sticky action rail 的组织方式，但当前已有 `ResourceDetailActionPanel`，无需引入外部侧栏组件。 |
| Table Components | https://21st.dev/community/components/s/table | 本阶段不接入链接列表。后续若恢复全部链接，可借鉴其密度控制，但移动端仍更适合分组列表卡。 |
| Tabs Components | https://21st.dev/community/components/s/tabs | 本阶段不新增“摘要 / 链接 / 元数据”切换。后续若做信息补全，可优先复用项目已有 Radix Tabs 与本地 UI tabs。 |

最终选择：不直接复制 21st.dev 的整组件。本阶段只借鉴 Card + Sticky Action Rail 的结构模式，落到项目已有 React、Tailwind、lucide-react、Radix UI、framer-motion 和本地组件体系中；Tabs / Table 相关方案保留为后续阶段参考。

## 5. 视觉方向

色彩策略：Restrained。页面以 `#F9FAFB` / `#F8FAFC` 浅灰背景、白色面板、深灰文本为主体，蓝色和青色只用于主操作、当前状态、链接类型强调和焦点状态，橙色仅保留给“重新搜索”等搜索启动动作。

场景句：用户在手机或桌面上快速检查一条网盘资源，环境可能是通勤、夜间或办公间隙；界面需要低压力、可快速扫读、清楚告诉用户下一步会发生什么。

参考锚点：

1. Linear / Notion 的任务型信息密度：不炫技，优先让用户理解结构。
2. Apple 系统设置的圆润浅面板：柔和但不粘腻。
3. Stripe 文档页的操作确定性：按钮、状态、说明都直接服务任务。

## 6. 信息架构

本阶段页面结构保持现有语义，只做视觉与文案收敛：

1. 顶部返回与上下文条
   - 左侧为返回搜索结果。
   - 右侧可显示来源入口或“来自上次搜索：关键词”，但不强依赖。
   - 移除“跟随显示”等实现感文案。

2. 资源首屏摘要区
   - 左侧：标题、来源、云盘类型、媒体类型、标签。
   - 右侧：预览图作为辅助判断材料。无图时展示轻量空状态，不使用装饰性插画。
   - 底部：打开前速览指标条。

3. 打开前速览
   - 链接数量。
   - 访问方式：直接打开 / 需要提取码 / 需手机扫码 / 磁力链接。
   - 资源体积。
   - 发布时间。

4. 主体内容区
   - 桌面：左侧主内容，右侧 sticky 操作面板。
   - 移动端：操作面板在首屏摘要后出现，不新增底部 sticky 操作条。
   - 主内容仍只承载当前摘要内容，不新增分段导航。

5. 操作面板
   - 主按钮：打开主资源 / 扫码转存 / 查看资源。
   - 次按钮：复制主链接、复制提取码、查看原始详情。
   - 状态说明：提取码状态、扫码状态、外部跳转提示。

后续阶段候选：

- 全部链接：若产品确认恢复，再按云盘类型分组展示备用链接。
- 元数据：若面向普通用户有价值，再以低优先级折叠区展示。
- 相关图片：若多图能帮助判断资源，再以缩略图辅助展示，不做内容站图库。

## 7. 布局规格

桌面端：

- 页面容器：`max-w-7xl`，左右内边距沿用 `container`。
- 首屏摘要：两列布局，主内容 `minmax(0, 1fr)`，预览图列约 `280px-360px`。
- 主体：`minmax(0, 1fr) + 320px` sticky action rail。
- 卡片间距：20px-24px。

移动端：

- 单列布局。
- 返回按钮和主操作按钮高度不低于 44px。
- 预览图使用稳定比例 `aspect-[4/5]` 或 `aspect-[16/10]`，根据图片类型决定，不让加载后撑动布局。
- 操作面板按钮可换行，主操作优先排第一行。

## 8. Soft UI Tokens

建议在资源详情页专属样式中使用以下语义 token，不新增大而全的设计系统。

| Token | 值 | 用途 |
| --- | --- | --- |
| `--rd-bg` | `#F8FAFC` | 页面背景 |
| `--rd-surface` | `#FFFFFF` | 面板、卡片 |
| `--rd-surface-muted` | `#F1F5F9` | 指标条、空状态底 |
| `--rd-border` | `#E2E8F0` | 轻边界 |
| `--rd-text` | `#111827` | 标题和关键值 |
| `--rd-body` | `#374151` | 正文 |
| `--rd-muted` | `#4B5563` | 次级说明 |
| `--rd-primary` | `#007AFF` | 主操作、焦点 |
| `--rd-cyan` | `#0891B2` | 云盘/选中辅助 |
| `--rd-search` | `#FF9500` | 搜索相关动作 |
| `--rd-success` | `#34C759` | 可用、已复制 |
| `--rd-danger` | `#FF3B30` | 错误、不可用 |

圆角：

- 按钮 / 芯片：12px 或 pill。
- 面板 / 卡片：16px。
- 首屏摘要容器：20px。
- 禁止常规容器继续使用 32px+。

阴影：

- 静态面板：优先轻边界，无阴影或 `0 2px 8px rgba(15, 23, 42, 0.06)`。
- 可点击卡片 hover：`0 8px 18px rgba(15, 23, 42, 0.08)`。
- sticky 操作面板：`0 10px 24px rgba(15, 23, 42, 0.08)`。
- 不再使用多层强发光、重 blur 玻璃和大面积渐变。

排版：

- 统一使用系统 sans 栈。
- H1：28px-36px，700，行高 1.15，字距 0。
- H2：20px-24px，650。
- 正文：15px-16px，行高 1.7。
- 元信息：13px-14px，保证对比度，不使用过浅灰。

## 9. 组件设计

### ResourceDetailHero

目标：从“暗色海报 hero”改为“资源摘要面板”。

设计：

- 浅色面板，圆角 20px。
- 标题区域不使用衬线字体，不限制到 14ch；改为 `max-w-[64ch]`，移动端允许 2-3 行自然换行。
- 标签使用浅底 pill，主云盘类型用蓝/青弱底色，媒体类型和目标类型使用灰底。
- 预览图放在独立图片框内，有图时 object-contain，无图时使用 `ImageIcon + 暂无预览图 + 判断提示`。
- “打开前速览”固定为四个指标卡：链接数量、访问方式、资源体积、发布时间；移动端两列或单列。

### ResourceDetailActionPanel

目标：让用户明确知道外跳前会发生什么。

设计：

- 标题改为“资源操作”。
- 状态区改为三行：主链接状态、提取码、外部打开方式。
- 主按钮用项目蓝或青色纯色，不使用渐变。
- 次按钮为白底轻边界。
- 禁用态保留说明，例如“暂无主链接”。
- 扫码转存态显示手机图标和“需在手机端完成”。

### ResourceDetailLinksSection（后续阶段候选）

本阶段不接入该组件，避免改变当前测试语义和产品行为。后续若恢复备用链接价值，应控制密度。

设计：

- 作为“全部链接”分段。
- 分组标题使用云盘名称 + 数量。
- 链接条目为浅面板列表项，不使用顶部渐变条；可用小图标或轻色 badge 表示类型。
- 每条链接操作按钮顺序：打开、复制链接、复制提取码。
- URL 使用次级文本和 break-all，避免横向溢出。

### ResourceDetailMetaSection（后续阶段候选）

本阶段不接入该组件。后续若确认元数据面向普通用户有价值，再保留可追溯字段，但不抢占主任务。

设计：

- 放入“元数据”分段。
- key/value 使用紧凑 definition list。
- 不在首屏展示大块元数据，避免用户误以为这是调试页。

### ResourceDetailGallery（后续阶段候选）

本阶段不接入图库。首图仅保留在 `ResourceDetailHero` 的辅助预览框中；后续若恢复图库，图片也只能作为判断辅助，不做内容站图库。

设计：

- 首图保留在摘要区。
- 其他图片默认折叠或横向缩略图。
- 无图不渲染图库区，避免空面板。

### ResourceDetailEmptyState

目标：降低用户丢失上下文的挫败感。

设计：

- 使用浅色空状态面板，不使用大面积渐变与玻璃背景。
- 文案保留两个明确动作：返回上一次搜索、重新搜索当前线索。
- 详情页关闭状态和上下文失效状态文案区分。

## 10. 状态清单

默认：

- 首屏显示标题、摘要指标、辅助预览图、主操作和摘要内容。

加载：

- 设置开关解析时使用骨架屏或轻量 spinner。
- 资源图片加载前保留固定比例占位。

空状态：

- 无资源上下文：返回上次搜索 / 重新搜索 / 回首页。
- 无摘要：显示“暂无摘要，建议先查看链接状态和来源信息”。
- 无图片：图片框内展示轻量说明。
- 无链接：操作面板禁用主按钮，并提供重新搜索。

错误：

- 复制失败：toast 说明“复制失败，请稍后重试”。
- 外链 URL 不合法：按钮禁用或提示“链接格式不可打开”。
- 扫码二维码过期：提示可刷新或返回来源页。

成功：

- 复制成功 toast。
- 打开资源前如需弹出密码/扫码弹层，应保持焦点可恢复。

交互：

- hover 只改变背景、轻阴影或 1px 位移。
- focus-visible 必须有可见 ring。
- active 使用轻微 `scale(0.98)`。
- disabled 移除 hover 位移，保留可读文字。
- reduced motion 下关闭 transform 入场，保留必要 opacity 或颜色反馈。

## 11. 实施建议

第一步：视觉收敛。

- 修改 `ResourceDetailHero`，移除暗色渐变 hero 和衬线标题。
- 修改资源详情相关 CSS，减少 gradient、blur、32px+ 圆角和强阴影。
- 保持现有 test id，降低测试迁移成本。

第二步：操作面板和空状态收敛。

- `ResourceDetailActionPanel` 标题改为“资源操作”，移除“跟随显示”，保留按钮数量和行为。
- `ResourceDetailEmptyState` 移除大面积渐变、玻璃和 blur 装饰，保留返回、重试搜索、回首页动作。
- 不改外部打开、复制、密码弹层、扫码转存和资源快照恢复逻辑。

第三步：质量验证。

- 保持 `frontend/src/pages/__tests__/ResourceDetailPage.test.tsx` 中关于“全部链接不渲染”“图库不渲染”的产品语义。
- 更新因文案收敛导致的文本断言，例如“资源操作台”“跟随显示”。
- 添加移动端布局测试或 Playwright 断言，覆盖 375px 和桌面宽度。
- 运行 `pnpm lint`、`pnpm test -- ResourceDetailPage`、`pnpm build`。

## 12. 验收标准

1. 首屏不再依赖暗色沉浸背景，用户能在 3 秒内判断资源是否值得打开。
2. 主操作、复制链接、复制提取码、扫码转存状态清晰可理解。
3. 当前页面信息结构保持不变，不新增全部链接、元数据、图库或底部 sticky 操作条。
4. 移动端无横向滚动，所有按钮触控高度不低于 44px。
5. 正文、按钮、辅助说明、错误文本符合 WCAG AA 对比度目标。
6. 不新增渐变文字、强玻璃拟态、装饰发光、32px+ 常规卡片圆角。
7. 页面仍保持 UniSearch “简洁、明了、可信”的产品气质。

## 13. 后续阶段待确认问题

1. 是否允许恢复“全部链接”区块？当前阶段不恢复；若后续恢复，需要同步改测试与产品预期。
2. 元数据是否面向普通用户展示？如果这些字段主要用于调试，应默认折叠或仅在开发/管理员模式显示。
3. 移动端是否需要底部 sticky 主操作？当前阶段不新增；若后续加入，要确保不遮挡摘要和链接内容。

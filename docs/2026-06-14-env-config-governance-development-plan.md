# 环境配置治理开发计划

> **目标：** 收敛根目录 `.env.example` 的职责边界，移除已经没有运行时价值的环境变量，保留确有必要的初始化/兜底配置，并让 README、Docker 默认值与代码语义一致。

## 1. 背景

当前项目的环境配置存在三类问题：

1. 运行时主配置、初始化兜底配置、部署脚本配置混在同一个 `.env.example` 中，使用边界不清。
2. `PLUGIN_COUNT` 仅用于启动早期估算默认并发，属于可从真实配置推导出的冗余变量。
3. `CHANNELS` 与 `ENABLED_PLUGINS` 已经不再是“日常运维事实来源”，更适合作为首次初始化与数据库/默认清单缺失时的兜底配置。

## 2. 设计原则

- **运行时事实优先**：数据库后台配置和运行时注册结果优先生效。
- **环境变量只做初始化与兜底**：仅在首次启动、空库或缺失配置时参与。
- **主模板聚焦主应用**：根目录 `.env.example` 只保留主应用运行时真正会读取的变量。
- **部署脚本独立管理**：仅供脚本使用的变量应从主应用模板中剥离，避免误导部署。

## 4. 当前决策

- `PLUGIN_COUNT`：删除。
- `CHANNELS`：保留，但降级为初始化/空库兜底配置。
- `ENABLED_PLUGINS`：保留，但降级为启动注册默认清单与临时覆盖配置。
- 部署脚本专用变量：从根目录主模板中拆出。

## 5. 风险与回退

- 如果删除 `PLUGIN_COUNT` 后默认并发异常，可临时通过 `CONCURRENCY` 显式覆盖。
- 如果 `CHANNELS` 拆分后空库初始化不完整，可暂时恢复环境变量兜底并补充迁移逻辑。
- 如果部署脚本仍依赖根目录 `.env.example`，则需同步更新脚本读取说明或提供独立模板。

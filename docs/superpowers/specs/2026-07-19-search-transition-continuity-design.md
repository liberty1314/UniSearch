# UniSearch 搜索过渡连贯性修复设计规格

生成时间：2026-07-19 10:00:00 +0800
状态：方案 1 已确认，等待书面规格审阅

## 1. 目标与范围

本次修复仅调整搜索页空态与结果态之间的过渡编排，不改变搜索请求、URL 同步、筛选器、结果卡片、登录流程或搜索历史。

成功标准：

- 提交搜索后，结果区从页面既定起点进入，不再先出现在空态画布下方再整体上跳。
- 中央搜索框继续平滑收拢为结果页顶部查询条。
- 从首页进入结果页后立即清空，空态搜索框仍保持完全可见、可聚焦和可输入。
- 普通清空、连续搜索和 `prefers-reduced-motion: reduce` 均保持可用。

## 2. 已验证根因

### 2.1 正向过渡跳动

`SearchTransition` 当前使用 `AnimatePresence mode="sync"`。退出中的空态画布高 512px，结果视图与它同时位于普通文档流中。浏览器关键帧显示：

- 过渡开始时结果视图位于 `y≈586px`。
- 空态退出期间结果视图仍位于 `y≈608px`。
- 空态卸载后结果视图瞬间回到 `y≈96px`。

因此查询条先跟随旧画布位于页面下方，随后一次性上跳约 512px。

### 2.2 快速清空后输入框消失

从首页进入搜索结果页后立即清空时，空态输入框实际仍在 DOM 与无障碍树中，但其共享布局父节点永久残留：

```text
opacity: 0.0440309
transform: translate3d(-35.8957px, -246.355px, 0) scale(1.23831, 1)
```

该状态在 1.6 秒后仍未恢复。根因是路由入场尚未稳定时反向触发同一 `layoutId`，Framer Motion 将结果查询条的投影状态交给新空态节点，但同步卸载中断了投影收尾。

## 3. 选定方案

采用 `popLayout` 与单向共享布局组合：

1. `SearchTransition` 改用 `AnimatePresence mode="popLayout"`，并提供相对定位上下文，使退出视图立即脱离文档流。
2. 结果视图从最终页面起点直接进入，避免空态高度影响结果位置。
3. 共享 `layoutId` 只用于“空态 → 结果态”的正向接管。
4. “结果态 → 空态”不复用共享投影；空态搜索框在自身最终位置执行短淡入与轻微位移。
5. 减少动态效果时关闭位移和共享布局，只保留短透明度变化。

不采用单一持久输入框，因为它需要重组 `SearchPage`、`SearchStage` 和 `SearchQueryDock` 的结构与控制归属，超出本次缺陷范围。不采用分阶段状态机，因为它会人为延迟结果挂载并增加额外状态。

## 4. 组件职责

### `SearchTransition`

- 记录前一视图，推导本次切换方向。
- 使用 `popLayout` 管理空态与结果态的占位关系。
- 向空态和结果态提供是否启用共享查询框布局的明确契约。
- 保持结果内容不被动画阻塞。

### `SearchStage`

- 继续承载空态标题、碎片场和搜索框。
- 只在正向接管准备阶段注册查询框 `layoutId`。
- 反向返回时使用稳定的原位入场，不继承结果查询条投影。

### `SearchQueryDock`

- 继续承载结果页查询框、返回操作和真实进度。
- 仅在从空态提交搜索时注册匹配的 `layoutId`。
- 直接 URL 访问结果页时不播放不存在来源节点的共享变形。

## 5. 数据流与边界

```text
searchParams.keyword
        │
        ▼
SearchPage 推导 idle/results
        │
        ▼
SearchTransition 推导 forward/backward
        ├── forward：popLayout + 共享查询框变形
        └── backward：popLayout + 空态原位淡入
```

- 输入仍由 `SearchBox` 和 `useSearchBoxController` 管理。
- 清空仍由现有 `clearResults()` 与 `/search` URL 替换完成。
- 不增加 Store 字段、定时器、请求延迟或全局动画状态。

## 6. 测试策略

### 组件测试

- 断言 `AnimatePresence` 使用 `popLayout`。
- 断言正向切换启用共享布局，反向切换禁用共享布局。
- 断言当前视图语义和减少动态效果分支保持正确。

### 浏览器回归

- 空搜索页提交后，过渡期间结果视图顶部不得因退出画布高度下移。
- 首页搜索进入结果页后，在查询条刚出现时立即清空；等待动画结束后空态输入框计算透明度必须为 `1`，且变换归零。
- 桌面与移动端均检查无横向溢出。
- 减少动态效果下验证输入框可见和结果内容立即可读。

### 全量验证

执行目标 Vitest、全量 Vitest、TypeScript 检查、ESLint、生产构建和 Playwright 搜索相关用例。

## 7. 风险、迁移与回滚

- `popLayout` 需要相对定位父级，否则退出节点的绝对定位可能参照错误祖先；组件测试与浏览器坐标断言覆盖此风险。
- 单向共享布局会让反向清空比正向提交更克制，这是有意设计，用于保证输入框稳定可见。
- 不涉及数据迁移、接口兼容或依赖新增。
- 回滚时恢复 `SearchTransition` 的原 Presence 模式和两个查询框原有 `layoutId` 即可；业务状态无需回滚。

# UniSearch 搜索页“聚合棱镜”设计规格

生成时间：2026-07-18 17:43:28 +0800
状态：方案已确认，等待书面规格审阅

## 1. 设计结论

搜索页采用“聚合棱镜”作为唯一创意母题：关键词进入由来源碎片组成的棱镜，碎片在搜索开始后拆解为真实来源节点，随渐进式搜索批次重新组合，最后转化为筛选条件、结果骨架和结果卡片。

UniSearch 的真实工作提供了创意来源：系统把不同来源的零散线索聚合成可以判断和打开的资源。

参考站点只提取设计方法：

- [In Pieces](http://www.species-in-pieces.com/#)：让碎片从散乱到成形成为内容变化本身，而不是背景特效。
- [Your Plan, Your Planet](https://yourplanyourplanet.sustainability.google/)：用单一视觉焦点、阶段式反馈和色彩分区降低复杂内容的认知负担。

本方案不复刻多边形动物、环保插画或全屏展示站结构。

## 2. 目标与成功标准

### 目标

- 在不降低搜索效率的前提下，使搜索页具有可识别、可记忆的视觉身份。
- 建立“输入意图 → 多源检索 → 批次聚合 → 结果成形”的连续因果。
- 让搜索等待时间展示真实进度，而不是静态骨架或虚假百分比。
- 保留现有搜索框、URL、筛选、结果卡片、视图模式、登录分支和渐进式数据流。

### 成功标准

- 用户操作搜索后 100ms 内获得可见反馈。
- 搜索结果一旦到达即可阅读，动画不得成为阻塞层。
- 快响应时主过渡在 700–900ms 内完成，不人为拖延搜索。
- 慢响应时只循环来源节点，不循环整页大动画。
- 桌面和移动端均无横向溢出；移动端活动碎片不超过 8 个。
- `prefers-reduced-motion: reduce` 下不出现循环位移、视差、爆散和错落卡片入场。
- 键盘、中文输入法、历史导航和辅助技术播报保持可用。

## 3. 范围

### 包含

- 无关键词搜索场景。
- 搜索框聚焦与输入反馈。
- 搜索提交后的棱镜拆解和来源聚合。
- 渐进式来源进度和部分结果到达。
- 查询条、筛选器和结果区的共享布局过渡。
- 刷新、空结果、错误、回退搜索和取消旧请求的视觉行为。
- 浅色、深色、移动端和减少动态效果。

### 不包含

- 修改后端搜索接口或渐进式事件格式。
- 修改搜索排序、去重、来源优先级和资源解析。
- 重写结果卡片业务、筛选字段或登录策略。
- 引入 WebGL、Canvas 粒子引擎、新动画包或远程插画资源。
- 将首页、热门页和后台同步改造成同一视觉主题。

## 4. 方向比较与选择

### 方案 A：聚合棱镜，采用

以 SVG 几何碎片表现来源和批次，能够与真实渐进式状态建立一一对应；搜索前具有识别度，结果阶段仍可保持工具效率。

### 方案 B：资源探索岛，不采用

以等距插画表现影视、文档、软件和云盘场景，亲和力强，但需要持续维护插画资产，且会把搜索工具误读为内容展览。

### 方案 C：数据碎片剧场，不采用

使用深色全屏、多边形爆散和强对比转场，视觉冲击最大，但长时间使用容易疲劳，与当前浅色品牌和结果信息密度冲突。

## 5. 页面视觉构图

### 5.1 搜索前桌面布局

```text
┌──────────────────── 顶部导航 ────────────────────┐
│                                                  │
│              把分散线索，拼成可用资源              │
│                                                  │
│        来源碎片       ◇ 聚合棱镜       来源碎片      │
│                                                  │
│   ┌────────────── 搜索输入框 ─────────────────┐   │
│   │ 搜索电影、剧集、文档或软件……          搜索 │   │
│   └──────────────────────────────────────────┘   │
│                                                  │
│          最近搜索轨迹        今日热门线索          │
│                                                  │
└──────────────────────────────────────────────────┘
```

- 首屏最小高度为导航以下可用视口，视觉重心位于视口上方约 44%。
- 标题只保留一句：“把分散线索，拼成可用资源”。
- 搜索框是唯一强操作，不增加第二个主按钮。
- 12–18 个棱镜碎片围绕搜索框布置，使用不同尺寸和透明度表达远近。
- “最近搜索轨迹”和“今日热门线索”位于首屏下部，使用紧凑横向条目，不再包裹于大面积启动台卡片。
- 当前匿名登录提示保留为搜索框下的一行说明，不进入棱镜视觉层。

### 5.2 搜索结果桌面布局

```text
┌──── 返回 ── “流浪地球” ── 8/10 来源完成 ── 刷新 ────┐
│ 网盘类型  来源  时间  包含词  排除词  高级筛选   视图  │
├──────────────────────────────────────────────────────┤
│      结果卡片       结果卡片       结果卡片            │
│      结果卡片       结果卡片       结果卡片            │
└──────────────────────────────────────────────────────┘
```

- 搜索框通过共享布局收拢为导航下方的吸附式查询条，关键词仍可编辑。
- 查询条右侧展示真实来源完成数；搜索完成后替换为结果总数。
- 常用筛选器显示为单行“校准片”；高级筛选继续复用现有筛选面板。
- 结果网格和列表模式继续使用现有用户偏好。
- 卡片顶部增加 2px 来源识别线，但平台名称和网盘类型仍以文本明确展示。

### 5.3 移动端布局

- 标题缩短为“拼出可用资源”，避免首屏文字挤压。
- 棱镜由最多 8 个碎片组成，不启用指针视差。
- 搜索框宽度为视口减 32px；软键盘出现后搜索框上移，但不切换页面。
- 最近搜索和热门线索改为横向滚动条目。
- 结果态查询条吸附在导航下；筛选器独立成为横向滚动行，高级筛选从底部面板打开。
- 结果默认列表视图，保持现有响应式偏好。

## 6. 视觉系统

### 6.1 色彩

| 语义 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| 页面底色 | `#F3F7F5` | `#06110F` | 冷瓷背景与夜幕背景 |
| 主文本 | `#102520` | `#F4FAF7` | 标题、正文和关键词 |
| 棱镜蓝 | `#335CFF` | `#6F8BFF` | 主操作、活跃来源和焦点 |
| 矿物青 | `#2DB7A3` | `#52D6C1` | 已完成来源和成功聚合 |
| 信号珊瑚 | `#FF6B52` | `#FF8A74` | 警告、失败和取消状态 |
| 雾线灰 | `#D9E5E1` | `#29423A` | 网格、边界和未完成来源 |

约束：不使用大面积紫色渐变；珊瑚色不作为普通装饰；来源状态不只依赖颜色，还必须有图标、文字或形态变化。

### 6.2 字体

- **展示标题**：MiSans Variable，字重 650，字距 `-0.025em`；未提供本地字体时回退现有系统字体栈。
- **正文和控件**：Noto Sans SC 与现有系统字体栈，字重 400–600。
- **来源、批次和时间**：IBM Plex Mono；无本地字体时回退等宽系统字体。
- 实施阶段优先自托管字体子集；若字体资产成本不合理，则保持系统字体，不通过远程字体阻塞首屏。

### 6.3 形态

- 棱镜碎片使用有明确折线的四边形和三角形，不使用随机圆点粒子。
- 页面主要面板圆角 18–22px，搜索框圆角 22px；结果卡片沿用现有圆角等级。
- 背景网格只在首屏和查询条附近可见，结果区逐渐淡出，避免与高密度内容竞争。
- 阴影保持短距离、低透明度；动效焦点通过边界、位移和颜色建立，不依赖大面积模糊光晕。

## 7. 核心交互

### 7.1 静置与聚焦

- 静置时碎片在 6–9 秒周期内进行不超过 6px 的低幅度漂移。
- 细指针设备允许最大 8px 的局部视差；触摸设备完全关闭。
- 搜索框聚焦后，最近的 4–6 个碎片向输入框偏转 3–6 度并移动 8–16px。
- 自动聚焦和手动点击必须进入同一视觉状态。

### 7.2 输入反馈

- 每次完成的字符输入触发一次轻微折射：离输入框最近的一个碎片亮起并移动 2–4px。
- 中文输入法组合期间不为拼音中间态触发；`compositionend` 后只触发一次。
- 同时活跃的字符反馈不超过 6 个；快速输入合并反馈，不逐字符排队播放。
- 输入反馈不读取、持久化或绘制具体字符内容，只根据有效查询长度改变棱镜完整度。

### 7.3 最近搜索与热门线索

- 最近搜索显示关键词、历史结果数和网盘类型摘要；删除与清空行为保持现有契约。
- 热门线索继续从真实热榜生成，不展示宽泛模板。
- 点击任一线索后，线索条目向搜索框方向移动 12px，同时填入关键词并开始正常搜索。
- 两类线索都不能绕过登录、URL 和筛选默认值逻辑。

## 8. 搜索过渡时间线

### 阶段 0：即时确认，0–140ms

- 搜索按钮收缩为蓝色脉冲节点。
- 搜索框锁定提交动作，但关键词保持清晰可读。
- 旧视觉时间线立即取消，只保留最新一次提交。
- 业务请求立即发出，不等待动画结束。

### 阶段 1：棱镜拆解，140–420ms

- 棱镜碎片沿预定义曲线路径向来源轨道展开，最大位移不超过视口短边的 12%。
- 背景网格向关键词中心收束 2–4px。
- 不使用全屏闪白、强缩放或超过 8px 的模糊。

### 阶段 2：来源聚合，420–780ms

- `totalSources` 决定可见来源节点数量；无总数时展示 3 个中性占位节点。
- `completedSources` 每增加一次，对应节点由线框变为实体。
- `receivedBatches` 每增加一次，来源轨道向结果区发送一个短脉冲。
- 进度文案使用“已完成 3/8 个来源”或“正在汇总首批结果”，不显示伪百分比。

### 阶段 3：结果揭示，首批结果到达后立即开始

- 搜索框通过 `layoutId` 收拢为顶部查询条。
- 已完成来源碎片展平为筛选芯片轮廓；未完成来源保留在查询条进度区。
- 结果骨架先出现，首批真实结果到达后在原位替换，避免布局跳动。
- 第一屏卡片以 35–45ms 间隔揭示；最多错落 8 张，其余直接显示。

### 阶段 4：搜索完成

- 来源进度替换为“共找到 N 条结果”。
- 未完成的占位节点淡出，完成节点合并为查询条右侧状态胶囊。
- 页面恢复完全可交互状态。

### 快响应规则

- 如果首批结果在 420ms 前到达，跳过完整来源轨道停留，在 700ms 左右完成共享布局。
- 不得为了播放完整动画把真实结果隐藏到 900ms 以后。

### 慢响应规则

- 780ms 后停止大幅度运动，只保留来源节点的低频呼吸和真实计数变化。
- 每个来源完成时播放一次 180ms 的闭合反馈，不重复拆解棱镜。

## 9. 状态机与数据流

```text
idle
  ├── 聚焦或输入 → composing
  ├── 线索点击 → submitting
  └── 减少动态效果 → static

composing
  ├── 有效提交 → submitting
  ├── 清空且失焦 → idle
  └── 匿名用户提交 → auth-handoff

submitting
  ├── progressive started → collecting
  ├── 普通搜索回退 → collecting-fallback
  ├── 错误 → error
  └── 新提交 → cancel-current + submitting

collecting / collecting-fallback
  ├── 首批结果 → revealing
  ├── 空结果完成 → empty
  └── 错误 → error

revealing
  ├── 搜索完成 → settled
  └── 新批次 → append-results

settled
  ├── 刷新 → refreshing
  ├── 修改关键词 → composing
  └── 修改筛选 → refreshing
```

### 数据所有权

- 搜索请求、取消、回退和结果仍由 `useSearchStore` 管理。
- 视觉状态机只读取关键词、加载状态、渐进式状态、来源计数、批次数和结果数量。
- 视觉层不得写入搜索结果，不得自行重试请求，也不得伪造来源完成。
- URL 同步继续由现有 Hook 和搜索服务完成。

## 10. 组件与动画边界

```text
SearchPage
├── SearchScene
│   ├── SearchPrism（纯视觉 SVG）
│   ├── SearchBox（既有业务组件）
│   └── SearchLaunchTracks（最近搜索与热门线索）
├── SearchTransitionStage（流程编排）
├── SearchQueryDock（结果态查询条）
├── SearchUnifiedFilterCard（既有筛选）
└── SearchResults（既有结果与资源操作）
```

### 职责

- `SearchPrism`：只渲染碎片、来源路径和状态映射，`aria-hidden` 且不接收指针。
- `SearchScene`：组织首屏布局、标题、搜索框和线索轨道，不执行请求。
- `SearchTransitionStage`：订阅真实搜索状态并管理一次性 GSAP 时间线；卸载或新搜索时销毁旧时间线。
- `SearchQueryDock`：结果态的可编辑关键词、进度、刷新与结果总数。
- `SearchResults`：继续拥有结果状态、网格/列表、无限加载和资源打开。

### 动画引擎边界

- GSAP 只控制 `SearchPrism` 内部 SVG 节点和过渡舞台的装饰层。
- Framer Motion 只控制搜索框、查询条、筛选器、结果骨架和结果卡片的布局与生命周期。
- 两个引擎不得同时控制同一个元素的 `transform` 或 `opacity`。
- CSS 负责长周期环境动画和主题变化。

## 11. 结果、刷新、空状态与错误

### 正常结果

- 首批结果到达后立即释放交互，后续批次在结果尾部或排序后的稳定位置加入。
- 新卡片只播放一次 180–240ms 的淡入与 8px 上移，不对已显示卡片重播入场。

### 刷新搜索

- 保留旧结果，不重新播放棱镜拆解。
- 查询条出现一次 480ms 扫描线；来源状态重新计数。
- 新结果完成后使用交叉淡入更新，避免全页骨架闪烁。

### 无结果

- 碎片停在未闭合状态，中心展示当前关键词和三个可执行建议。
- 有筛选条件时优先提供“清除筛选”；无筛选时提供精简关键词建议。
- 不使用情绪化文案，明确下一步操作。

### 错误

- 珊瑚色只标记失败来源和错误状态；搜索框与已有结果保持可用。
- 提供“重新搜索”，并保留当前关键词和筛选。
- 渐进式失败后普通搜索回退时显示“已切换为完整搜索”，不表现为错误完成。

### 匿名用户

- 输入和提交反馈可以发生，但不播放“结果已开始聚合”的错误暗示。
- 登录跳转继续保存当前关键词和搜索参数；返回后从提交阶段重新进入真实搜索。

## 12. 无障碍与减少动态效果

- 棱镜、轨道和脉冲全部 `aria-hidden="true"` 且 `pointer-events: none`。
- 真实来源进度使用礼貌级 `aria-live`，每个来源完成不重复朗读全部页面。
- 搜索框、清空、搜索、返回、刷新和筛选保持现有可见焦点。
- 动画不通过颜色单独表达完成、失败或等待。
- 减少动态效果下：
  - 禁止漂移、视差、拆解、曲线飞行和卡片错落。
  - 搜索框在 150–200ms 淡入结果查询条。
  - 进度以静态文本和节点填充变化表达。
  - 业务请求和结果出现不增加任何等待。

## 13. 性能约束

- 桌面活动碎片不超过 18 个，移动端不超过 8 个。
- 同时运行的来源脉冲不超过 4 个，超过部分合并为一次批次反馈。
- 循环动画只使用 `transform`、`opacity` 和 SVG `stroke-dashoffset`。
- 背景模糊不逐帧变化；结果区不使用大面积 `backdrop-filter` 动画。
- 指针视差使用 `requestAnimationFrame` 写 CSS 变量，不进入 React state。
- 搜索开始、新搜索、路由离开和组件卸载时清理 GSAP 时间线、定时器和动画帧。
- 低性能或窄屏设备自动使用更少碎片和更短时间线。

## 14. 测试与验收

### 单元与组件测试

- 搜索视觉状态能从空态进入提交、收集、揭示、完成、回退、错误和刷新。
- 视觉状态只订阅 Store，不修改搜索结果和请求状态。
- `totalSources`、`completedSources`、`receivedBatches` 与节点状态映射正确。
- 首批结果提前到达时，过渡能提前进入揭示阶段。
- 新提交能取消旧时间线，旧请求状态不能驱动新视觉。
- 中文组合输入只在完成后触发一次折射。
- 减少动态效果时不创建 GSAP 拆解时间线。
- 装饰层对辅助技术隐藏且不拦截指针。

### 页面回归测试

- 无关键词时仍展示搜索框、最近有效搜索和热榜线索。
- 匿名用户仍保留搜索意图并进入登录页。

## 16. 规格自审

- **占位检查**：无 `TBD`、`TODO`、未定义状态或待定接口。
- **一致性检查**：创意母题、真实进度、组件职责和动效时间线使用同一数据语义。
- **范围检查**：不改搜索接口、排序、登录和资源操作；只新增视觉编排并调整搜索页布局。

- **独特性检查**：真实来源碎片、批次脉冲和结果成形取代了泛用蓝色渐变；签名元素只服务 UniSearch 的多源聚合语义。
